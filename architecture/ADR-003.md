# ADR-002: Post-RAG Agent Execution, Authorization, and Human Approval Architecture

**Status:** Accepted  
**Date:** 2026-08-25

---

## Context

NIYAM is an institutional AI teammate designed to assist users with
institutional tasks such as:

- laboratory booking,
- student information retrieval,
- maintenance ticket generation,
- certificate generation,
- and other institutional workflows.

The system initially implemented a Retrieval-Augmented Generation (RAG)
layer capable of retrieving relevant institutional policy documents and
providing those policies to the AI reasoning layer.

After implementing the RAG layer, the architecture needed to evolve from
a system that could only reason about institutional policies into a system
that could safely perform institutional actions.

The core problem was:

> An AI model may propose an action, but it must not be trusted as the
> authority that determines whether the action is authorized or safe to
> execute.

The architecture therefore required:

1. Authentication of institutional users.
2. Role-based authorization.
3. Separation between AI reasoning and actual action execution.
4. Tool-level authorization enforcement.
5. Policy-driven decisions.
6. Human approval for actions requiring institutional oversight.
7. Auditability of decisions and executed actions.
8. Protection against cross-user and cross-institution access.
9. A stable API contract that can support additional institutional tools.

---

# Decision

NIYAM will use a layered architecture in which the AI reasoning system
can propose actions, but institutional backend services remain the final
authority responsible for authentication, authorization, approval, and
execution.

The primary execution pipeline is:

```text
User
  │
  ▼
Authentication
  │
  ▼
JWT Identity + Role
  │
  ▼
Agent API
  │
  ▼
AI Reasoning Service
  │
  ├── Intent Classification
  ├── Policy Retrieval through RAG
  ├── Policy Reasoning
  └── Proposed Action
          │
          ▼
   ┌───────────────────────┐
   │ Decision Evaluation   │
   └───────────────────────┘
          │
    ┌─────┴──────┐
    │            │
  ALLOW       APPROVAL
    │            │
    ▼            ▼
 Tool       Approval Queue
 Execute         │
    │            ▼
    │          Admin
    │            │
    │       ┌────┴────┐
    │       │         │
    │    APPROVE    REJECT
    │       │         │
    ▼       ▼         ▼
 Result   Execute   No Execution
